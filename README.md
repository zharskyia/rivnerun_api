scrape-config.json
Конфіг правил скрейпінгу сайту rivnerun.club для Android-застосунку Rivne Running Club. Застосунок не має доступу до бекенду сайту, тому отримує дані (новини, тренування, забіги, товари, рекорди, партнерів тощо) шляхом розбору HTML публічних сторінок за допомогою регулярних виразів. Цей файл виносить ці регулярні вирази з коду застосунку назовні, щоб їх можна було виправити одразу після зміни верстки сайту — без випуску нової версії APK.

Як це працює
При кожному запуску застосунок намагається завантажити цей файл за URL, зашитим у SCRAPE_CONFIG_URL (ScrapeConfig.kt у репозиторії rivnerun.club_android) — зараз це raw-посилання на цей файл у гілці main цього репозиторію.
Якщо файл успішно завантажився і є валідним JSON — застосунок кешує його локально (SharedPreferences) і одразу використовує.
Якщо мережа недоступна або файл не завантажився — застосунок бере останню успішно закешовану версію.
Якщо кешу ще немає (перший запуск без мережі) — застосунок використовує вбудовані в код Kotlin значення за замовчуванням (ScrapeConfig.default()), ідентичні вмісту цього файлу на момент останньої синхронізації.
Тобто зміни тут впливають на застосунок одразу після наступного запуску з інтернетом, без оновлення в Google Play.

Формат файлу
Кожне поле — рядок з регулярним виразом у синтаксисі Java/Kotlin Regex. У JSON зворотний слеш (\) і лапки (") всередині значення екранується подвійним зворотним слешем/бекслешем (\\, \") — це стандартне екранування JSON, не специфіка проєкту.

Більшість патернів починаються з (?is) — це inline-прапорці: i (регістронезалежний пошук), s (крапка . матчить і символ нового рядка). Їх не варто прибирати, інакше матчинг багаторядкового HTML зламається.

version
Номер версії конфіга (зараз 1). Інформаційне поле, застосунок його не перевіряє.

home
Патерни для головної сторінки (/).

Поле	Призначення
descriptionMeta	Витягує вміст <meta name="description" content="..."> для короткого опису на екрані "Головна".
article
Спільні патерни для всіх "текстових" сторінок (/club, /istoriya, /zasnovniki, /partneri, /contacts, /donate, /rekordi-klubu).

Поле	Призначення
articleTag	Знаходить вміст тега <article>...</article>.
bodyDivMarker	Усередині статті знаходить відкриваючий тег <div itemprop="articleBody">; застосунок далі сам рахує вкладеність <div>, щоб коректно вирізати весь блок до відповідного закриваючого тега.
news
Патерни для архіву новин (/news).

Поле	Призначення
articleLink	Знаходить посилання <a href="/...">...</a>, що веде на окрему новину.
image	Картинка новини (очікується шлях виду /img/500/...).
title	Заголовок новини всередині <strong>.
date	Дата у форматі ДД.ММ.РРРР всередині <span>.
training
Патерни для розкладу тренувань (/training, а також блок розкладу на сторінці /rekordi-klubu).

Поле	Призначення
table	Таблиця з класом training-schedule__info.
row / cell	Рядок (<tr>) і клітинка (<td>) таблиці.
firstParagraph	Перший <p> у клітинці з днем/датою/часом.
date / time	Дата (у <strong>) і час (у <span>) всередині firstParagraph.
removeStrong / removeSpan	Використовуються, щоб прибрати дату/час з тексту й лишити лише назву дня.
paragraph	Параграфи в другій клітинці (назва тренування, локація).
races
Патерни для списку забігів (/events).

Поле	Призначення
listDivMarker	Контейнер <div class="...race-list...">.
link	Посилання на окремий забіг усередині списку.
titleStrong / titleHeading	Назва забігу — спершу шукається в <strong>, якщо немає — у заголовку <h1>–<h6>.
date	Дата всередині <time> або <span>.
products
Патерни для каталогу товарів (/shop).

Поле	Призначення
link	Посилання на товар (очікується шлях /tovar/...).
image	Картинка товару.
title	Назва товару в <strong>.
price	Ціна в <span>.
records
Патерни для сторінки "Рекорди клубу" (/rekordi-klubu) — єдина сторінка з вкладками.

Поле	Призначення
tabsList	Контейнер <ul class="tabs__list"> з назвами вкладок.
tabTitle	Назва окремої вкладки (<span> усередині tabsList).
tabsContentMarker	Контейнер <div class="tabs__content">, що містить по одному <div> на кожну вкладку (в тому ж порядку, що й tabsList).
paragraph	Параграфи всередині вкладки. Логіка групування: перший непорожній <p> після порожнього <p><br></p> (або перший параграф вкладки) вважається заголовком групи (напр. "ЧОЛОВІКИ" або ім'я спортсмена); наступні непорожні параграфи до наступного роздільника — записи цієї групи. Ця логіка в коді застосунку, не в конфізі — якщо сайт змінить структуру розбиття на групи, саме регулярку paragraph відредагувати не вийде, доведеться міняти код.
partners
Патерни для логотипів партнерів на сторінці /partneri.

Поле	Призначення
listDivMarker	Контейнер <div class="...partners__list...">.
link	<a href="..."> з посиланням на сайт партнера, що обгортає логотип.
image	Картинка логотипу всередині link.
Фолбек-механізм при помилці
Для кожного поля при декодуванні JSON діє окремий fallback: якщо секція (home, news, records...) або конкретне поле відсутнє в файлі — береться значення з вбудованого дефолту, а не весь конфіг цілком. Тобто можна редагувати/додавати лише ті секції, які реально зламались, не переписуючи весь файл.

Якщо патерн синтаксично невалідний як регулярний вираз — парсинг відповідної сторінки впаде з винятком у рантаймі (видно в Logcat з тегом ClubSiteRepository), і застосунок покаже користувачу востаннє закешовані дані для цього розділу замість помилки на екрані.

Як редагувати безпечно
Відкрийте реальну сторінку сайту (view-source:https://rivnerun.club/...) і знайдіть фрагмент HTML, який змінився.
Складіть/перевірте регулярний вираз (зручно — у будь-якому онлайн-тестері regex з прапорцями i та s).
Екрануйте \ → \\ і " → \" при вставці рядка в JSON.
Перевірте, що version файлу лишається валідним числом, а JSON в цілому — валідним (помилка парсингу всього файлу відкидає весь конфіг і застосунок відкочується на кеш/дефолти).
Закомітьте й запуште в гілку main цього репозиторію — зміна набуде чинності для користувачів автоматично, при наступному запуску застосунку з мережею.
Діагностика на реальному пристрої
Якщо після зміни верстки сайту якийсь розділ застосунку показує старі/кешовані дані або попередження на кшталт "Не вдалося оновити N розділ(и)", підключіть пристрій і подивіться лог:

adb logcat -s ClubSiteRepository:W

Там буде видно, яка саме сторінка (/path) і з якою помилкою не розібралась — це вказує, яке поле конфіга потребує виправлення.

Пов'язаний репозиторій
Kotlin-код, що читає й застосовує цей конфіг (ScrapeConfig.kt, ClubSiteRepository.kt, NewsRepository.kt), живе в репозиторії застосунку: rivnerun.club_android. Цей репозиторій (rivnerun_api) містить лише дані — самого коду застосунку в ньому немає.
